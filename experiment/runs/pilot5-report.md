### 기준선 치유 — 두 모델 모두 턴 1, 훅 exit 2 한 번 뒤

- **Opus 턴 1.** 회원 기능을 쓰면서 `Member` 를 순수 Java 로 바꿨다(E3). 첫 훅 exit 2(R2·R3·R4·R7)를 받자 바로 이렇게 말했다.

  이어서 `common/DateUtils` 삭제, `findRaw` 제거, `BookController` 의 유스케이스 전환을 같은 턴에 했다. 커밋 메시지는 "회원 등록·조회 API 추가 및 기존 아키텍처 위반 정리" 다.

  - 응답: "기존 코드에서 아키텍처 규칙을 어기던 부분도 함께 고쳤습니다. 새 기능을 넣자 아키텍처 검사 훅이 이 위반들 때문에 막았습니다."

## 2. 한도 소모 표

`quota_*` 는 세션 직전·직후 탐침이다. 턴별 값은 `turn.json` 의 `rate_limit_utilization` 이다. 사용률은 CLI 가 소수 둘째 자리로 주므로 **해상도는 1%p** 다.

| | Haiku L3 (pilot4) | Sonnet L3 | Opus L3 |
|---|---|---|---|
| 세션 시간 | 61.6분 | 19.7분 | 36.3분 |
| 입력 토큰(캐시 포함) | 14.77M | 4.84M | 6.06M |
| 출력 토큰 | 287k | 107k | 150k |
| 비용 (API 단가 환산 추정, 실제 청구 아님) | $0.571 | $3.954 | $10.731 |
| 5시간 창 사용률 | 0.13 → 0.14 (턴 값) | 0.10 → 0.17 | 0.27 → 0.29 (턴 2), 17:40 창 초기화, 0.01 → 0.10 |
| **5시간 창 소모** | **≈ +1%p** | **+7%p** | **≈ +12%p** (초기화 전 +2, 후 +10) |
| 주간 사용률 | 0.24 → 0.24 | 0.27 → 0.27 | 0.26 → 0.27 |
| **주간 소모** | **< 1%p** (해상도 미만) | **< 1%p** (해상도 미만) | **+1%p** (반올림 구간으로 0~2%p) |

- **주간 %p 는 해상도 미만이다.** 두 세션을 합쳐도 0.26 → 0.27 이다. 반올림을 감안하면 두 세션의 주간 소모 합은 0~2%p 다.
- **세션당 주간 소모는 5시간 창 소모로 환산해 추정했다.**
  - 같은 구간(pilot5 전체)에서 5시간 창 소모 합은 약 19%p(12 + 7), 주간 증가는 1%p(0~2)다.
  - 그래서 주간/5시간 비율은 약 0.05(상한 0.11)다.
  - 세션당 주간 소모 추정:

    | 모델 | 점추정 | 상한(반올림 구간) |
    |---|---|---|
    | Opus | ≈ 0.6%p | 2%p |
    | Sonnet | ≈ 0.4%p | 1%p |
    | Haiku | ≈ 0.05%p | 1%p |
- **실측하지 않은 것:**
  - Sonnet·Opus 의 L0~L2 세션.
  - 아래 계산은 모든 수준에 L3 값을 쓴다. L3 는 리뷰어 호출이 더해져 가장 비쌀 것으로 본다. Haiku 에서 L0·L1 은 L3 비용의 약 0.6 배였다.
- **비용 상한:** Opus $10.7, Sonnet $4.0 이므로 `{"sonnet": 15, "opus": 30}` 은 L3 실측의 약 3.8배, 2.8배 여유다.

### 본 실험 예상 소요

수준마다 세션당 값은 Haiku 를 pilot3·4 실측 평균(시간 33.4분, 5시간 창 1%p), Sonnet·Opus 를 위 L3 값으로 두었다. 비용은 API 단가 환산 추정이며 실제 청구가 아니다.

|---|---|---|---|---|---|---|
| `main.json` 기본안 (Opus 2반복) | 68 (H 28, S 28, O 12) | 약 32시간 | 약 370%p (5시간 창 3.7개분) | 약 20%p / 80%p | **1주 미만** (연속 실행 2일 내외) | 약 $250 |
| Opus 5반복 | 84 (H 28, S 28, O 28) | 약 42시간 | 약 560%p (5.6개분) | 약 30%p / 112%p | **약 1주** (상한 쪽이면 주간 창 2개에 걸침) | 약 $420 |

- **계산:**
  - 시간 = H 28 × 33.4 + S 28 × 19.7 + O n × 36.3 분.
  - 5시간 창 = H 28 × 1 + S 28 × 7 + O n × 12.
  - 주간 = 위 세션당 추정 × 세션 수.
- **5시간 창은 묶이지 않는다.** 연속으로 돌리면 32시간에 5시간 창이 6.4개 지나가므로, 창당 평균 약 57%p(84세션 안은 약 67%p)를 쓴다.
  - 다만 Opus 세션이 무작위 순서로 몰리면 창 하나에서 100% 에 닿을 수 있다. Opus 8세션 ≈ 96%p 다.
  - 그때는 러너의 대기·재시도가 작동해야 한다(3절, 실물 미확인).
- **6주는 넘지 않는다.** 상한 쪽 가정에서도 2주 이내다. 조건이 있다: 주간 창에 다른 사용량이 많지 않아야 한다. 이번 주 기준선은 0.26 이었고, 다음 초기화는 2026-10-22 11:00 KST 다.

## 3. 한도 응답 실물과 러너 감지

- **이번에도 실제 거부(`status: rejected`)는 일어나지 않았다.** 5시간 창 최대값은 0.29 였다. 그래서 거부 응답 원문, 재시도 시각 정보의 유무, 러너 감지 로직이 실제 형태와 맞는지는 **여전히 확인하지 못했다.** 러너의 한도 감지 로직은 바꾸지 않았다.
- **확인한 것:**
  1. 5시간 창 초기화가 세션 도중(Opus 턴 3, 17:40)에 일어났다. 턴별 `rate_limit_utilization` 이 0.29 → 0.01 로 떨어지고, `resetsAt` 이 1792226400 → 1792244400(22:40)으로 바뀌었다. 러너는 이를 오류로 다루지 않고 계속 돌았다.
  2. 탐침과 매 응답의 `rate_limit_event` 는 `status: allowed` 였다. 탐침 응답에는 `rateLimitType: five_hour`, `overageStatus: rejected`, `overageDisabledReason: out_of_credits`, `isUsingOverage: false` 도 함께 있었다. 한도를 넘으면 초과 사용으로 넘어가지 않고 거부된다는 뜻으로 읽힌다.
  3. 창은 `five_hour`·`seven_day` 둘뿐이었다. 모델별 주간 창(예: Opus 전용)은 응답에 없었다.
- **본 실험에서 첫 거부가 나면 확인할 것:** `turn-NN/stream.rate-limited-1.jsonl` 의 원문, `turn.json` 의 `rate_limit_resets_at_attempts`, 대기 시간. README "구독 실행"에 기록한다.

## 5. 설계자 결정 사항

- **(a) Opus 반복 수 (2 유지 / 5 상향)**
  - **5로 올려도 한도 측면의 제약은 작다.** 2절 기준으로 Opus 5반복(84세션)은 순수 실행 약 42시간, 주간 소모 약 30%p(상한 112%p), API 환산 비용 상한 약 $420 이다(실제 청구 아님).
  - 남는 위험은 두 가지다.
    1. 주간 상한 쪽 가정이면 주간 창 두 개에 걸친다.
    2. Opus 세션이 몰리면 5시간 창 거부가 나는데, 그 경로는 실물로 검증되지 않았다.
  - `max_cost_usd 800` 은 두 안 모두 충분하다.
- **(b) 예상 소요가 6주를 넘으면 Sonnet 반복을 줄일지**
  - **해당 없음.** 두 안 모두 2주 이내로 추정된다. Sonnet 반복을 줄일 근거는 없다.
- **(c) 사전 등록 가능 상태인가 — 남은 코드 변경**
  - **필수 코드 변경은 없다.** 다만 등록 전에 정할 조건이 셋 있다.
    1. **리뷰어 비동기와 `ScheduleWakeup`.** Haiku·Sonnet 은 리뷰어를 비동기로 띄웠다. Haiku 는 `ScheduleWakeup` 으로 기다렸고, Opus 는 동기로 불렀다. 모델마다 대기 방식이 달라 시간 지표가 섞인다. 리뷰어 판정 자체는 세 모델 모두 기록됐다. `--disallowedTools ScheduleWakeup` 같은 도구 제한은 하네스 조건 변경이므로 지금 정하거나 "그대로 둔다"를 등록 문서에 적어야 한다.
    2. **훅 지문 미갱신**(`limit` 뒤 다음 턴 첫 호출에서 archTest 가 돎, pilot4 보고서). 하네스 동결 대상이다. 그대로 두려면 알려진 동작으로 등록한다.
    3. **한도 거부 경로가 실물로 검증되지 않았다.** fake 로만 확인했다. 본 실험 중 첫 거부가 나면 `turn.json` 기록으로 확인하고, 감지가 틀리면 그 세션만 다시 돌린다는 규칙을 등록 문서에 둘 것을 권한다.
  - 이번에 고친 summarize 세션 이름 표기(모델이 둘 이상이면 이름에 모델)는 보고서용이다. 측정에는 영향이 없다.
